# HandBook: backend

Для университетского HandBook я написал сервер на Kotlin и связал его с [Android-клиентом](https://github.com/NolReaction/HandBook_Client). Это был мой первый опыт собственного backend: я разбирался с HTTP API, аккаунтами, авторизацией и запросами к SQL-базе.

Я сделал регистрацию с подтверждением email, вход с выдачей JWT, восстановление пароля через письмо и HTML-форму. Через API можно получить профиль, изменить имя, загрузить каталог мест и сохранить историю выбранных мест. Пароли аккаунтов хешируются через BCrypt.

При старте сервисы создают свои таблицы и заполняют демонстрационный каталог. Этот проект я сохранил как учебную работу, полноценным публичным сервисом его пока не считаю.

## Код и технологии

Я использовал Kotlin 2.1.10, Ktor 3.1.1 с Netty, kotlinx.serialization, PostgreSQL через JDBC, JWT, BCrypt и JavaMail. В коде есть отдельная ветка подключения к embedded H2, но обычный запуск использует PostgreSQL.

- [Application.kt](src/main/kotlin/Application.kt): подключение модулей Ktor.
- [Routing.kt](src/main/kotlin/Routing.kt): HTTP-маршруты.
- [Security.kt](src/main/kotlin/Security.kt): проверка JWT.
- [service](src/main/kotlin/service) и [Databases.kt](src/main/kotlin/Databases.kt): SQL и работа с данными.
- [data/model](src/main/kotlin/data/model): модели запросов и ответов.
- [EmailSender.kt](src/main/kotlin/EmailSender.kt): отправка писем.
- [application.yaml](src/main/resources/application.yaml) и [RuntimeConfig.kt](src/main/kotlin/RuntimeConfig.kt): конфигурация.

Зависимости указаны в [build.gradle.kts](build.gradle.kts) и [libs.versions.toml](gradle/libs.versions.toml).

## Запуск

Нужны JDK 17, своя PostgreSQL и доступ к зависимостям Gradle. В проекте используется Gradle Wrapper 8.4. Все команды ниже выполняются из корня; в Windows используй `gradlew.bat` вместо `./gradlew`.

1. Создай локальную базу `handbook` и пользователя `handbook` со своим паролем и правами на создание таблиц. Отдельного инструмента миграций в проекте нет.
2. Задай переменные окружения процесса или Run Configuration в IDE по таблице ниже. Не записывай секреты в файлы репозитория.
3. Для регистрации и восстановления пароля настрой почту. `EmailSender` использует `smtp.mail.ru`, SSL-порт 465 и пароль приложения для почтового аккаунта.
4. Запусти сервер:

```bash
./gradlew run
```

API работает на порту 8080. После успешного запуска каталог можно проверить по адресу <http://localhost:8080/places>. Адрес сервера в Android-клиенте задаётся отдельно, в `RetrofitProvider`.

| Переменная | Что указать |
| --- | --- |
| `HANDBOOK_DATABASE_URL` | JDBC URL; по умолчанию `jdbc:postgresql://localhost:5432/handbook` |
| `HANDBOOK_DATABASE_USER` | Пользователя БД; по умолчанию `handbook` |
| `HANDBOOK_DATABASE_PASSWORD` | Пароль своей БД; обязателен, значения по умолчанию нет |
| `HANDBOOK_JWT_SECRET` | Собственный случайный ключ подписи JWT; обязателен, значения по умолчанию нет |
| `HANDBOOK_SMTP_FROM` | Адрес отправителя и SMTP login; нужен для отправки писем |
| `HANDBOOK_SMTP_PASSWORD` | Пароль приложения SMTP; нужен для отправки писем |
| `HANDBOOK_PUBLIC_BASE_URL` | Базовый URL для ссылок в письмах; по умолчанию `http://localhost:8080` |

Для JWT можно локально сгенерировать ключ командой `openssl rand -hex 32` и передать его через окружение. URL из письма должен открываться на устройстве получателя: `localhost` подойдёт только для браузера на самом сервере. Если письмо открывается на телефоне, укажи доступный ему LAN-адрес или hostname.

Раньше в репозитории были опубликованы реквизиты БД и почты. Из текущей конфигурации они удалены, но остаются в истории Git. Если эти сервисы ещё действуют, реквизиты нужно сменить у провайдера.

## Проверки

Тесты чтения конфигурации можно запустить отдельно, без БД и почты:

```bash
./gradlew test --tests com.example.RuntimeConfigTest
```

Четыре теста проверяют обязательные значения, отказ при пропущенном или пустом секрете и локальные значения по умолчанию. Они прошли отдельным запуском JUnit 4.13.2: файлы `RuntimeConfig.kt` и `RuntimeConfigTest.kt` скомпилированы Kotlin 2.2.21 с language/API version 2.1 и JVM target 17. Сервер, БД и почта при этом не запускались; YAML и подключение параметров также проверены статически.

Полная сборка пока не подтверждена: в окружении проверки загрузка Wrapper 8.4 была недоступна, а установленному Gradle 8.13 в offline-режиме не хватило Kotlin plugin 2.1.10 в cache. Зависимости проекта ради этой проверки не менялись.

Старый `ApplicationTest` запускает модуль приложения, которому нужна БД. Общий `./gradlew test` поэтому не является автономной проверкой. Подключаться к прежнему удалённому серверу для знакомства с проектом не нужно.

Перед публичным использованием здесь ещё нужно проверить обработку ошибок и доступ, настроить HTTPS, миграции и интеграционные тесты. Я оставил проект вместе с клиентом, чтобы можно было проследить весь путь запроса от Android-экрана до базы данных.
